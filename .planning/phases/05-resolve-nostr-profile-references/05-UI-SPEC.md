# Phase 5 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

This phase is not a new screen. Raw `nostr:nprofile` / `nostr:npub` in the article body become inline markdown links. No new chrome, colors, type roles, or components. Mentions reuse the reader’s existing `textLink` style and tap into the existing `ProfileScreen`.

Sources: `05-CONTEXT.md` D-01–D-09, `05-RESEARCH.md` mention rewrite / `readerLinkAction`, `DESIGN.md` Face Split, `ui/theme/Color.kt`, `ui/theme/Type.kt`, `UserSettings` link colors, webapp `NostrMentionLink.tsx`, `ReaderScreen.kt` markdown `textLink`, `Profile.displayName`.

| 2xl | 48px | Unused this phase. Do not inflate inline mention hit targets to 48dp |

Exceptions:

## Typography

Mentions inherit article body type. Do not introduce a mention size, weight, or italic. Do not put sans on mention labels.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 14sp | 500 (Medium) | 1.43 (`labelLarge` 14/20). Unused this phase |
| Body | 16sp | 400 (Regular) | 1.5. Unused this phase |
| Heading | 16sp | 500 (Medium) | 1.5. Unused this phase |
| Article (existing, mention uses this) | 21sp default | 400 | 1.71 (`bodyLarge` 21/36) |

Weights this phase may use: 400 only on mention text (same as surrounding body). Do not bold or underline mentions independently of other markdown links.

Usage:

- Mention label: same `body` `TextStyle` as the paragraph it sits in (`settings.fontSize`, reading font, justify). Color comes from Color, not from a second type role
- Custom markdown labels (`[Gigi](nostr:nprofile1…)`) keep the author’s characters and the same body type (D-03)
- Invalid identifiers: truncated plaintext in body type, not link type

## Color

Dark is first-class. Light uses the paper column. Do not add a new theme or a mention-only color.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#18181B` dark / `#FFFFFF` light | Reader background (`colorScheme.background`). Unchanged |
| Secondary (30%) | `#27272A` dark / `#F5F5F5` light | Existing elevated fills. Mentions are not cards |
| Accent (10%) | `#6366F1` (`Indigo500`) | Reserved list below. Not for mentions |
| Destructive | not used | No destructive actions in this phase |

Accent reserved for:

- Existing filled CTAs elsewhere in the app (unchanged)
- Mentions are **not** accent. They are reading links

Reading link color (existing `ReaderScreen` `textLink`; mentions must use this exact path):

| Token | Default | Usage |
|-------|---------|-------|
| `linkColorDark` | `#38BDF8` (`Sky400`) | Article markdown links in dark, including mentions |
| `linkColorLight` | `#3B82F6` (`Blue500`) | Article markdown links in light, including mentions |
| Unset fallback | `colorScheme.secondary` | Same `readingColor(...)` call as today’s links |

User Settings already let the reader pick link color. Mentions follow `settings.linkColorDark` / `linkColorLight`. Do not hard-code Sky/Blue if the user overrode them.

`textLink` contract (existing `ReaderScreen.kt`): `body.copy(color = linkColor).toSpanStyle()`. Mentions get that `SpanStyle` and no other. If other article links underline, mentions underline; if they do not, mentions do not. Do not add a hover/pressed fill, badge, or avatar.

Invalid / undecodable `nostr:nprofile`: body color (`colors.onBackground`), not link color. Not tappable.

Focal point:

- The article paragraph stays the visual anchor. A mention is inline text, same visual weight as `[example](https://…)`
- Do not paint SpokenMark, FindMark, or NIP-84 highlight colors on mentions
- Opening a mention uses existing `ProfileScreen` chrome (title `Profile.displayName`, Back). Do not restyle that screen this phase

## Copywriting Contract

No new on-screen chrome strings. Visible copy is the link label in the article.

| Element | Copy |
|---------|------|
| Primary action | Tap `@name` (no button). Opens the existing in-app profile |
| Raw mention label | `@` plus `Profile.displayName(pubkeyHex, cachedKind0)`. Example with kind 0 name `Gigi`: `@Gigi`. Example without kind 0: `@npub1abcde12…` using `Profile.shortNpub` (`npub.take(12)` + `…`) |
| Custom markdown label | Keep the author’s label verbatim. `[Gigi](nostr:nprofile1…)` stays `Gigi`, not `@Gigi` (D-03) |
| Empty state heading | none (zero mentions: no extra UI) |
| Empty state body | none |
| Error state | none as chrome. Invalid identifier is truncated plaintext, not a snackbar or dialog |
| Invalid identifier | First 20 characters of the original identifier, then `…`. Not a link. No crash |
| Destructive confirmation | none |
| Profile screen title | existing `Profile.displayName` (unchanged) |
| TTS | After rewrite, speech uses the markdown link label (`@name` or the custom label), not the bech32 blob |

Do not show a loading word, “Resolving…”, or placeholder avatar alt text (D-02).

## Surfaces

### 1. Inline mention in the article body (D-01, D-02, D-03)

The only visual surface this phase adds. It is a markdown link inside `ReaderScreen` `Markdown`, after `Footnotes.expand` + `NostrMentions.rewrite`.

| Input | Visible label | Style | Tappable |
|-------|---------------|-------|----------|
| Raw `nostr:nprofile1…` / `nostr:npub1…` / `nostr://` same | `@` + `Profile.displayName` | existing `textLink` | yes |
| `[Gigi](nostr:nprofile1…)` | `Gigi` (unchanged) | existing `textLink` | yes |
| Undecodable `nostr:nprofile…` | truncated plaintext | body color | no |
| Bare `nprofile1…` / `npub1…` | original plaintext (D-09) | body color | no |
| `nostr:nsec1…` / `note` / `nevent` / `naddr` | not a profile mention (D-05) | today’s reader routing | today’s behavior |

Rules:

- Text only. No avatar, no leading `@` icon, no spinner (D-02)
- One rewrite at first paint. Cached kind 0 name if `EventCache` already has it. Do not remount `rememberMarkdownState` when kind 0 arrives later (scroll and selection must survive)
- Href stays `nostr:{encoded}` so nprofile relay hints survive. Do not rewrite to a `/p/{npub}` path
- Logged out: same labels, same taps, same profile screen (READ-01). No login sheet
- Code fences and inline code: do not rewrite (existing `Footnotes.protectCode` pattern)

### 2. Existing profile screen (D-04)

Tap → `readerLinkAction` `OpenProfile(pubkeyHex)` → `Routes.profile(npub)` → existing `ProfileScreen`.

Do not add a mention-specific header, banner, or “opened from article” chip. Title, Back, and overflow stay as they are.

## Interaction

| Action | Result |
|--------|--------|
| Tap `@name` or a custom-label profile link | Navigate to existing in-app profile for that pubkey. Login not required |
| Tap existing `naddr` / `note` / `nevent` | Unchanged (`OpenInReader` / `OpenExternal`) |
| Tap http(s) markdown link | Unchanged |
| Long-press article text that includes a mention | Existing selection / highlight path. Mentions are still text |
| Kind 0 arrives after paint | Label may stay short npub until the next article paint. Do not jump scroll or kill selection |
| Share/paste a profile URI on Home | Must not open the reader as an article (`UrlExtractor.articleUrl` stays null for profiles) |

## Motion

- None. Mentions appear with the parsed article. No fade-in of `@name`
- Profile navigation uses existing NavHost. No custom shared-element or avatar fly-in
- Reduced motion: nothing extra to disable

Flat-By-Default: no shadow, card, or outline around a mention.

---

## Accessibility

- The accessible name is the visible link text (`@name` or the custom label). Do not set a hidden contentDescription that replaces it
- Inline hit target matches other markdown links. Do not add a 48dp invisible box that overlaps neighboring words
- TTS speaks the label after rewrite, not the bech32
- RTL: mention is ordinary inline text; it follows article direction
- Invalid truncated identifier is readable text, not an image or icon
- Do not announce a live region when kind 0 resolves

---

## Out of scope (deferred, do not draw)

Avatars next to mentions, auto-linking bare `npub1` / `nprofile1`, treating `note` / `nevent` / `naddr` as profile mentions, a new profile chrome, mention chips, hover cards, follow buttons in the article.
