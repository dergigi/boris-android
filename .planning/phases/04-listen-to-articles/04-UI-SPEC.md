# Phase 4 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

This phase adds listen chrome to an existing Jetpack Compose / Material 3 app. It does not introduce shadcn, Tailwind, or a new type scale. Tokens below are the subset this phase may use; article body type and Home login chrome stay as they are in `DESIGN.md` and `ui/theme/`.

Sources: `04-CONTEXT.md` D-01–D-19, `04-RESEARCH.md` follow-along / top-bar / mini-player / settings, `DESIGN.md` Face Split, `ui/theme/Color.kt`, `ui/theme/Type.kt`, webapp `TTSSettings.tsx` / `TTSControls.tsx`, `ReaderScreen.kt` top bar, `SettingsScreen.kt` Reading category, `HighlightMarks.kt`.

## Typography

Listen chrome uses sans. Do not put Source Serif on play, speed, mini-player, or Settings TTS controls. The spoken mark sits on existing article type (`bodyLarge` 21sp / 36sp) and does not change it.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 14sp | 500 (Medium) | 1.43 (`labelLarge` 14/20) |
| Body | 16sp | 400 (Regular) | 1.5 |
| Heading | 16sp | 500 (Medium) | 1.5 (`titleMedium` 16/24) |
| Article (existing, not restyled) | 21sp | 400 | 1.71 (`bodyLarge` 21/36) |

Weights this phase may use: 400 and 500 only. Do not introduce 700 on listen chrome.

Usage:

- Heading: Settings subsection title `Text-to-Speech`
- Body: Settings row labels (`SettingRow` already uses `bodyMedium`; keep), preview paragraph, missing-TTS body copy
- Label: mini-player title, `{rate}x` on speed chips, snackbar / inline error, dropdown menu items

Preview paragraph: 16sp Regular, line-height 1.5, `onBackground`, wrap (never truncate). Exact sentence in Copywriting.

## Color

Dark is first-class. Light uses the paper column. Do not add a new theme.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#18181B` dark / `#FFFFFF` light | Reader and Settings backgrounds (`colorScheme.background`) |
| Secondary (30%) | `#27272A` dark / `#F5F5F5` light | Mini player surface, TTS preview box (`surfaceVariant` / elevated fill). 1dp outline `#3F3F46` dark / `#E5E7EB` light |
| Accent (10%) | `#6366F1` (`Indigo500`) | Reserved list below. Not for the spoken paragraph |
| Destructive | not used | No destructive actions in this phase |

Accent reserved for:

- Existing filled CTAs elsewhere in the app (unchanged)
- Settings speed chip in its selected/pressed state uses `colorScheme.primary` the same way `FontSizeButton` / `IconToggle` already do
- Mini-player and top-bar play/pause stay on-surface icon chrome, not indigo FABs

Spoken paragraph is a semantic state color, not a brand accent (same class as Find, not Home yellow):

| Token | Value | Alpha | Usage |
|-------|-------|-------|-------|
| SpokenMark | `#2DD4BF` | `0.38f` (match `FindMarkAlpha`) | Filled round-rect on the current spoken paragraph only |
| FindMark (existing) | `#93C5FD` | `0.38f` | In-article find. Do not reuse for speech |
| HighlightMine (existing) | `#FDE047` | `0.45f` | NIP-84 mine. Do not reuse for speech |
| HighlightFriends (existing) | `#F97316` | `0.45f` | NIP-84 friends |
| HighlightOther (existing) | `#9333EA` | `0.45f` | NIP-84 other |

`DESIGN.md` Two Loud Colors Rule still holds for brand chrome (indigo actions, yellow Home/NIP-84 marks). Find already added a transient blue. Spoken teal is the listen equivalent: fill like Find, never underline, never yellow.

> state coverage and REFERENCES those rows rather than restating the copy (de-dup).

Applicable state considerations resolved: 8 covered, 0 backstop, 0 unresolved

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | media (article speech), form (preview is never empty) | ✅ covered | No speakable paragraphs: Listen stays visible; tap shows empty-state heading/body. Preview box always contains the locked sentence |
| loading | interactive-control (Listen), media (engine init) | ✅ covered | First Play starts the service; top-bar icon stays PlayArrow with no spinner. If init has not finished, ignore duplicate taps |
| error | interactive-control, media, form | ✅ covered | Engine or language failure keeps Listen visible and shows the matching error copy plus Open settings (`Settings.ACTION_TEXT_TO_SPEECH_SETTINGS`). Reading layout unchanged |
| populated | media (playback), list-collection (paragraphs) | ✅ covered | Speaking: Pause in top bar; spoken fill + auto-scroll when follow-along is on and not user-paused; mini player when the current route is not that article |
| partial | form (settings), list-collection (follow-along) | ✅ covered | User scroll while speaking pauses auto-scroll only; speech continues; mark stays on the current paragraph. Play or skip resumes auto-scroll |
| overflow | nav (mini player), static-content (top-bar title) | ✅ covered | Mini-player title and reader top-bar title: 1 line, end ellipsis. Preview wraps. Language menu scrolls if the screen is short |

| long-text | static-content (preview), interactive-control (speed), nav (mini player) | ✅ covered | Preview wraps at 16sp/1.5. Speed label is short (`3x`). Mini-player title ellipsizes; tap still opens the article |

## Surfaces

### 1. Reader top bar (D-16)

Insert an `IconButton` in `actions` after Save (when present) and before overflow `MoreVert`.

| State | Icon | contentDescription |
|-------|------|--------------------|
| Idle / paused / stopped | `Icons.Filled.PlayArrow` | Listen |
| Speaking | `Icons.Filled.Pause` | Pause |

Rules:

- Visible on `ReaderUiState.Ready`, logged in or out
- Visible when TTS init failed (D-11)
- 48dp `IconButton`, same tint as Back / More (`colorScheme.onSurface`)
- Do not put Listen only in the overflow menu
- Do not add skip or speed to the top bar (those live on the mini player and in Settings)
- Loading / Error reader states: omit Listen (no article to speak)

### 2. Mini player (D-17, D-18)

Slim bar, always reachable while a session is active and the user is not on that article.

Placement:

- Tab destinations (Home, Library, Feed, You, Settings, …): sit directly above `BorisBottomBar` inside the shell `Scaffold` `bottomBar` slot (player then nav)
- Reader of a *different* article (no bottom bar): overlay the bottom of that reader, above system gesture insets
- Reader of the *speaking* article: hide the mini player; top bar owns play/pause

Layout (56dp tall, `surface` / `surfaceVariant`, 1dp outline on the top edge, no drop shadow):

```
[ title ……………… ] [ 2.1x ] [ prev ] [ play/pause ] [ next ]
```

- Title: `labelLarge` 14sp Medium, 1 line ellipsis, `weight(1f)`, contentDescription `Open article`. Tap navigates to `Routes.reader(url)`
- Speed: outlined 8dp chip, sans 14sp Medium, `{rate}x`, contentDescription Cycle speed. Cycles the locked preset list and writes `ttsDefaultSpeed`
- Prev / play / next: 48dp IconButtons, contentDescriptions Previous paragraph / Pause or Listen / Next paragraph
- Play uses PlayArrow when paused; Pause when speaking
- Do not show a progress bar, artwork, author line, or stop button on the in-app bar (Stop is on the system notification)

Hide when the session is null or the article has ended.

### 3. Settings: Text-to-Speech (D-06, D-08, D-09, D-10, D-13)

New `TtsSection` inside `SettingsCategory.Reading`, after `ReadingSection`, before `ReadingPreview`. Not a new top-level category. Not under Media.

Order:

1. Heading `Text-to-Speech` (`titleMedium`, `onBackground`)
2. `SettingRow` Default Playback Speed → speed cycle chip (gauge/`Icons.Filled.Speed` 18dp + `{rate}x`)
3. `SettingRow` Speaker language → `ExposedDropdownMenuBox` + read-only `OutlinedTextField`, 8dp corners, same pattern as `FontDropdown`, width fills the control slot
4. Preview box: 12dp padding, 8dp corners, `surfaceVariant` fill, exact preview sentence, 16sp / 1.5
5. Preview play: trailing `IconButton` PlayArrow/Pause, contentDescription Listen / Pause. One-shot utterance of the preview sentence. Does not open a mini player. If an article is speaking, preview stops it
6. `SettingCheckbox` Follow along while listening (default on)

If TTS is missing, keep every control visible and add the error body plus a text button Open settings under the preview.

### 4. Follow-along mark (D-12, D-13, D-15)

- Transient `PaintedHighlight` id `"spoken"`, filled, never underline
- Color `SpokenMark` `#2DD4BF` at `0.38f`
- Quote is the current paragraph’s display text
- Paint even when `showHighlights` is false
- Auto-scroll with existing `HighlightJump` / `scrollTarget`; ignore that motion as user scroll
- Manual scroll: stop auto-scroll, keep speaking, keep the mark
- Play or skip: resume auto-scroll
- Checkbox off: no mark, no auto-scroll

### 5. System media notification / lock screen (D-01, D-04)

Not Compose. Contract for what the user sees:

- Title: article title, else URL
- Artist: author if known, else omit
- Compact: play/pause, previous paragraph, next paragraph
- Expanded / headset: Stop as well
- Never put article body in the notification

### 6. Volume keys (D-19)

No extra chrome. While speaking, disable `VolumeKeys.Handle` so keys change volume. They do not scroll and they do not skip.

## Interaction

| Action | Result |
|--------|--------|
| Listen on this article | Start (or resume) at the paragraph nearest saved reading position; from the top if none |
| Listen on another article | Stop the current session; start the new article |
| Browse without Listen | Current speech continues (D-02, D-03) |
| Pause | Speech stops; session, mini player, and spoken mark remain |
| Resume | Restarts the current paragraph (mid-paragraph resume is best-effort, not required) |
| Skip next at last paragraph | Session ends; mini player dismisses; mark clears; top bar shows Listen |
| Skip previous at first paragraph | No-op |
| Speed cycle while speaking | Writes `ttsDefaultSpeed`, applies rate, restarts the current paragraph at the new rate |
| Preview play | Speaks the locked sentence only; no mini player |
| Open settings (error) | `Settings.ACTION_TEXT_TO_SPEECH_SETTINGS` |
| Notification permission (API 33+) | Request once on first Listen. Denial does not hide in-app controls or block reading |

## Motion

- Follow-along scroll: existing `animateScrollTo` used by highlight jump. No new bounce or parallax
- Mini player: appear/disappear with a 200ms fade, no slide that covers article text longer than that
- Spoken mark: instant fill on `onStart`; clear when the session ends. No pulse or blink
- Reduced motion: still auto-scroll (it is the point of follow-along). Do not add extra animation

Flat-By-Default: no drop shadow on the mini player. Tonal surface plus 1dp top outline.

---

## Accessibility

- Every listen icon has a contentDescription from Copywriting (never null)
- Touch targets 48dp on reader and mini player
- Preview sentence is real text, not an image
- Speakable content is the article the user already sees; do not add a live region that double-reads the paragraph
- RTL: row of mini-player controls mirrors; title still ellipsizes at the end
- Do not put paragraph text in Toasts
