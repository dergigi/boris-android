# Phase 6 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

This phase is not a new screen and not a visual redesign. Ordinary http(s) articles start fetching the origin and extracting Markdown on-device. The only UI change is two locked error strings on the existing `ReaderScreen` `ReaderUiState.Error` column. Loading, Ready, top bar, Try again, and Open original stay as they are.

Sources: `06-CONTEXT.md` D-12–D-14 (copy), D-08/D-11 (thin extract is a failure), D-09/D-10 (retry and no WebView stay invisible), D-15 (cache is Ready, not a badge), `06-RESEARCH.md` Pattern 2 / Pitfall 7, `DESIGN.md` Face Split, `ui/theme/Color.kt`, `ui/theme/Type.kt`, `ReaderScreen.kt` Error column, `ReaderViewModel.kt` `ReaderUiState.Error`, `strings.xml` `reader_open_original`.

## Copywriting Contract

Two sentences, verbatim. Put them in `strings.xml` as `reader_error_unreachable` and `reader_error_no_article`. Repository `IOException` messages must match these strings exactly. `ReaderViewModel` shows `e.message`. Drop `Failed to fetch readable content (…)` and the fallback `Failed to load this article.`

| Element | Copy |
|---------|------|
| Fetch failed (network, timeout, DNS, non-2xx after one UA retry, live fail with no origin cache) | `Could not reach this page.` |
| No article found (thin extract, not HTML, cookie wall, JS shell, paywall teaser after D-08 / D-11) | `Could not find an article on this page.` |
| Primary CTA | `Try again` (existing filled button, existing `onRetry` → `viewModel.load`) |
| Secondary CTA | `Open original` (existing outlined button; string `reader_open_original`). Show when `state.url` is not blank. Required on both errors (D-14) |
| Empty state heading | none. A near-empty extract is Error, not an empty Ready (D-08) |
| Empty state body | none |
| Error state | One of the two sentences above. Then Try again. Then Open original if the URL is present |
| Destructive confirmation | none |
| Blank URL (existing, not this phase) | `No URL to read.` Keep. Do not fold it into the two new strings |
| ViewModel null-message fallback | `Could not reach this page.` Never `Failed to load this article.` |

Forbidden on screen (D-13):

- Jina, `r.jina.ai`, jsoup, Readability, extract, User-Agent, browser retry, HTTP status codes, “401”, “proxy”, library names

Do not add a subtitle under the sentence. Do not toast the same error. Do not show a snackbar for fetch or extract failure.

## Surfaces

### 1. Existing reader Error column (D-12, D-13, D-14)

The only surface this phase touches. `ReaderScreenContent` `when (state) is ReaderUiState.Error`: centered `Column`, message `Text`, filled Try again, outlined Open original if `state.url.isNotBlank()`.

| Outcome | `state.message` | Open original |
|---------|-----------------|---------------|
| Fetch / network fail, no origin cache | `Could not reach this page.` | yes if URL present |
| Thin extract / not HTML / no article | `Could not find an article on this page.` | yes if URL present |
| Live fail, origin cache is a good extract | not Error: Ready | n/a |
| Blank URL (existing) | `No URL to read.` | no (url blank) |

Rules:

- Same layout, type, and buttons as today. Swap message strings only
- Both error kinds share one column. Do not split into two screens or two icons
- Logged out: same errors, same buttons (READ-01). No login sheet
- Nostr article/note/profile and RSS errors stay on their current paths. This contract is the ordinary http(s) extract path

### 2. Existing Loading and Ready

Unchanged. Loading still uses the current spinner / preview. Ready still uses `ArticleBody`. Highlights, TTS, find, and Open original in the overflow menu stay.

## Interaction

| Action | Result |
|--------|--------|
| Open an ordinary http(s) URL that extracts | Existing Ready reader |
| Open a URL that cannot be reached | Error: `Could not reach this page.` Try again. Open original |
| Open a URL whose extract is thin | Error: `Could not find an article on this page.` Try again. Open original. Do not show a teaser body |
| Tap Try again | `viewModel.load()` again. Existing Loading, then Ready or Error |
| Tap Open original | Existing `openOriginalArticle(context, url)` |
| Tap Back | Existing `onBack` |
| UA retry after 401/403/thin first pass | Invisible. User stays on Loading until Ready or one of the two Errors |
| Airplane / live fail with a prior origin cache | Ready if the cached extract passes the 500-char bar; otherwise no-article Error |

## Accessibility

- The error sentence is visible text. It is the accessible name of the failure. Do not replace it with an icon `contentDescription`
- Try again and Open original keep visible labels. Do not turn them into icon-only
- Do not announce a live region for the invisible UA retry
- RTL: column stays centered; strings are English resources like the rest of the reader
- TalkBack must never hear Jina, jsoup, User-Agent, or status codes
